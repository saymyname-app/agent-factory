# B — Inventaire de l'observabilité déterministe de l'Agent Factory (état existant)

Inventaire factuel de ce que le **code** (pas un agent LLM) capture, stocke, vérifie, affiche ou alerte sur la santé, l'avancement et la correction de l'usine. Aucune cible, aucune proposition : ce qui existe, comment c'est prouvé, et ce qui est câblé dans la cité qui tourne vs. seulement documenté.

Jargon (défini une fois) :
- **Gas City (`gc`)** : l'orchestrateur (superviseur + contrôleur) qui lance les sessions d'agents et exécute les *orders* (tâches planifiées ou déclenchées par événement).
- **Beads (`bd`)** : le tracker de travail (base Dolt) ; un *bead* est un ticket ; ses `metadata` (clés `gc.*`) servent de magasin d'état.
- **Order** : fichier `orders/*.toml` lu par le contrôleur ; déclencheurs `condition` (un `check` évalué à chaque tick, ~30 s), `cron`, `event`, `cooldown`.
- **Porte (door)** : un script `bin/` qui est le seul écrivain autorisé d'un état (ex. `escalation-door` pour `gc.needs_benjamin`).
- **Rig** : un dépôt produit enregistré dans la cité (`saymyname-backend`, `saymyname-frontend`) ; le dépôt Factory lui-même est le rig HQ.
- **Convoi marqué / nouveau flux** : un convoi (graphe de tickets) portant `gc.flow.mark=new-flow/v1`, avancé par code (`convoy-advance`) et non par le Mayor.
- **NEEDS BENJAMIN** : la liste des décisions qui attendent l'opérateur, lue par `bin/escalation-door list`.
