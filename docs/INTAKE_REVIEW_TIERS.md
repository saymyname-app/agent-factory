# Existing-code review tiers — reusable intake protocol

Companion to `decisions/ADR-0021-existing-code-review-tiers.md` and
`decisions/ADR-0015-project-intake-and-target-contract.md`. This document is
the reusable artifact: the escalation rule and the prompt templates, kept
separate from the ADR so a future takeover project (or a re-run on SayMyName
after V1) can be pointed at this file directly instead of re-deriving the
protocol.

Scope: this protocol runs against `evidencedBlock` entries (capabilities,
criteria, journeys) whose `origin.discovery` evidence marks them as
takeover-derived — i.e. found in an existing codebase during intake Pass 1,
not authored by the Factory through normal delivery. Factory-authored blocks
already went through a PR and CI review; they do not need this protocol.

## Escalation rule (mechanical, not left to model judgment)

| condition | tier to run |
| --- | --- |
| block is non-reserved and tier 1 finds nothing to flag | stop at tier 1 → `reviewed_ok` |
| block is non-reserved and tier 1 flags something | run tier 2 |
| block intersects a reserved class (`identity_and_consent`, `irreversible`, `money`, `authority`, `legal` — ADR-0015 §3 table) | always run at least tier 2, regardless of tier 1 result |
| tier 2 concludes with justified confidence | stop → `reviewed_ok` or `needs_rework` |
| tier 2 is inconclusive, or the block is reserved-class and still ambiguous after tier 2 | run tier 3 |

A block never skips straight to tier 3. A reserved-class block never stops at
tier 1 alone.

## Tier 1 — static (0 tokens)

No model call. Deterministic checks only, against the files/routes/tests the
block's `discovery` evidence cites:

1. Do the block's own tests pass right now (`ctest`/`pytest`/`npm test` etc.,
   whichever the rig uses)?
2. Is CI green for the last commit touching those files?
3. Run `/code-review` at effort `low` against the cited diff/file — does it
   surface correctness findings?

Record the three answers as `review.ref` evidence entries (`kind: "scan"` or
`"test"` as appropriate). If all three are clean: `review.state =
"reviewed_ok"`, `review.tier = "static"`, done. Otherwise, or if the block is
reserved-class, continue to tier 2.

## Tier 2 — model-assisted (bounded, one call per block)

Prompt template:

```
You are reviewing an existing piece of SayMyName code that intake discovered,
not code the Factory wrote. Your job is to say whether it should be trusted
as SayMyName V1's shipped behavior, exactly as it stands, or whether it needs
rework, replacement, or deletion.

Block: {block.title}
Description: {block.description}
Target statement (what this is supposed to do): {origin.statement}
Discovery evidence: {discovery_evidence_refs}
Tier-1 findings: {tier1_findings}

Answer with:
1. verdict: "reviewed_ok" or "needs_rework"
2. notes: concrete justification citing the evidence above — no invented
   claims, no praise/criticism without a cited reason
3. if needs_rework: a one-line summary suitable for an origin.conflicts[]
   entry (what the code does vs. what the target says), and which of
   keep_target / adapt_target / mix you'd recommend Benjamin consider — you
   are recommending, not deciding; the decision itself stays a reserved
   `outcome` question for the human.

Do not execute anything. Do not modify code. This is a read-only judgment
call.
```

Record the model's verdict as `review.state`, `review.tier = "model"`,
`notes` verbatim. If `needs_rework`, create the `origin.conflicts[]` entry per
ADR-0015 §5b and raise the reserved `outcome` decision — do this
mechanically from the model's structured output, don't let the model itself
write into `origin.conflicts[]` or resolve the decision.

## Tier 3 — human E2E (reserved, not default)

Only reached when tier 2 is inconclusive, or the block is reserved-class and
tier 2's verdict alone isn't enough to close it. Produces:

- A short click-through protocol: 3-6 concrete steps ("open X, do Y, expect
  Z"), written by the PO, not generated by a model call against the block's
  evidence and target statement.
- Surfaced in the cockpit as an ordinary `decision_required` — never a
  campaign stop. The campaign keeps working on other eligible items while
  this sits open, exactly like any other pending decision.
- Benjamin's own pass through the protocol is the evidence; the result
  (`reviewed_ok` / `needs_rework`) is recorded the same way as the other two
  tiers, with `reviewed_by` set to his name instead of `"factory:<tier>"`.

## What this protocol does not do

- It does not decide `keep_target` / `adapt_target` / `mix` — that stays a
  reserved human decision every time, per ADR-0015 §5b, regardless of which
  tier raised the conflict.
- It does not run automatically on Factory-authored code — only on
  takeover-discovered blocks.
- It does not replace normal PR review for *new* work the Mayor produces
  going forward; that continues through the existing delivery pipeline
  (`DELIVERY.md`).
